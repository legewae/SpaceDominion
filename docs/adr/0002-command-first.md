# ADR-0002: Команда — единственный способ изменить состояние

- **Статус:** принято
- **Дата:** 2026-11-27
- **Контекст:** лекция: «если необходимо получить код, который удовлетворяет SOLID, то
  каждый метод интерфейса следует заменить на команду»; event storming-диаграммы
  описывают домен в терминах команд, событий и политик.

## Решение

Любое изменение состояния домена выполняется объектом `ICommand`:

- команда создаётся фабрикой `ICommandFactory` по имени (`Commands.<Name>`) и аргументам;
- команда получает зависимости через конструктор, а не через `Ioc.Resolve`;
- после успешного изменения команда публикует доменное событие;
- политика (обработчик события) создаёт следующую команду и отправляет её в очередь.

`ICommand` наследует `App.ICommand`, чтобы один интерфейс подходил и домену, и контейнеру.

## Последствия

- Новое поведение = новый класс + регистрация; существующий код не правится (OCP).
- Команды можно ставить в очередь, логировать, оборачивать декораторами (ретрай, права,
  обработка ошибок) не меняя домен.
- Цена: больше классов, чем «метод в сервисе»; нужна дисциплина именования и регистрации.
- Доменные объекты становятся «данными без поведения» (property-bag), поведение живёт в
  командах. Это осознанный обмен: он позволяет генерировать адаптеры и сериализовать
  состояние, но требует дисциплины, чтобы правила не расползлись по командам.

## Альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| Сервисы с методами (`MatchService.StartMatch`) | нарушает OCP при каждом новом действии, не ложится в очередь команд |
| Анемичные DTO + сервис-слой | поведение и данные разделены формально, но нет единой точки расширения и трассируемости к диаграммам |
