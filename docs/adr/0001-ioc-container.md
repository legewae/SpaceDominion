# ADR-0001: IoC-контейнер — `App.Ioc` + `App.Scopes` из `Common/`

- **Статус:** принято
- **Дата:** 2026-11-27
- **Контекст:** ограничение преподавателя — использовать тот же контейнер, что и в
  эталонном репозитории `spacegame`; новые NuGet-пакеты нежелательны.

## Решение

Используем контейнер преподавателя, поставляемый двумя сборками:

- `Common/core.dll` (v0.1.0.0) — `App.Ioc.Resolve<T>(string name, params object[] args)`, `App.ICommand`;
- `Common/scopes.dll` (v1.0.0.0) — `App.Scopes.InitCommand`, `RegisterDependencyCommand`,
  `SetCurrentScopeCommand`, `ClearCurrentScopeCommand`, `DependencyResolver`.

Обе подключаются как `<Reference>` с `HintPath` в `..\Common\` в проектах Lib и Tests,
копируются в репозиторий как есть. Регистрация зависимостей — команда
`Ioc.Resolve<App.ICommand>("IoC.Register", "<имя>", (object[] args) => ...)`.

## Последствия

- Поведение и API совпадают с эталоном — преподавателю проще проверять.
- Нет внешних пакетов и restore-сюрпризов.
- В репозитории лежат бинарные зависимости без исходников: обновить контейнер можно
  только заменой dll.
- Поведение скоупов в многопоточном режиме неизвестно — обязательный спайк в PR-06.

## Альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| Autofac / Microsoft.Extensions.DependencyInjection | прямое нарушение ограничения |
| Собственный `Ioc` (как в первой версии эталона) | именно этот путь эталон прошёл и переделывал: PR #52 затронул 23 файла |
| Самописный контейнер «с нуля» | дублирование уже готового контейнера преподавателя, лишний объём |
