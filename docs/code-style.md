# Соглашения по коду

## Комментарии

- Только обычные комментарии `//`. XML-документация (`///`, `<summary>`, `<remarks>`,
  `<param>`) не используется: в Visual Studio она читается только как подсказка и
  засоряет код, а нам важна читаемость исходников.
- Комментарий объясняет **почему**, а не **что**: что делает метод, видно по имени.
- Комментарий ставится над объявлением с отступом его уровня; между объявлением и
  комментарием пустой строки нет.
- Длинные пояснения разбиваются на несколько строк `//` по ширине около 100 символов.
- Язык комментариев — русский, идентификаторы — английские.

## Имена

- Классы и методы — `PascalCase`, поля — `_camelCase`, локальные — `camelCase`.
- Команды заканчиваются на `Command`, события — на прошедшее время (`MatchCreated`),
  политики — на `On<Event>`, проекции — на `Projection`.

## Форматирование

- 4 пробела, LF, финальный перевод строки, без хвостовых пробелов — см. `.editorconfig`.
- Проверка в CI: `dotnet format --verify-no-changes`.

## Чего не делаем

- Не оставляем закомментированный код — для истории есть git.
- Не пишем комментарии-очевидности вида «// выполнить команду» над `command.Execute()`.
- Не используем `#region` для группировки: структура задаётся папками и именами.
